# 06 実装計画
工数は未見積。以下は依存順序と完了条件であり日付の約束ではない。

## フェーズ0: 土台
既存リポジトリを確認、技術選定、型/スキーマ、デモ領域、画面ルーティング、CIを作る。schema_version=1、calculation_version=1を定義。空状態の全画面が開ければ完了。

## フェーズ1: 計算の確立（P0）
金額/時間、段階料金、売上モード、経費、投資配賦、現金回収を純粋関数で実装。fixturesと受入A01〜A10をテスト。料金や利益をUIから独立して検証できたら完了。

## フェーズ2: 記録と投資（P0）
IndexedDB、設定、簡易記録、任意詳細入力、装備プラン/購入の分離、履歴編集と削除、データ移行を実装。再起動後の保存と過去料金固定を確認。予定プラン変更で実績が変わらなければ完了。

## フェーズ3: ダッシュボードと分析（P0）
ホーム、期間損益、配賦後時給、現金回収、期間フィルタ、入力品質表示を実装。日/週/月の合計と原票が突合できること。稼働なしの月の固定費・配賦額も表示する。

## フェーズ4: 計画とルール助言（P1）
手動3シナリオ、利用可能枠、重複排除、GO/WAIT/STOP、次課金カウントを実装。AI未接続でも全フローが通ること。

## フェーズ5: 持ち出しと品質（P0/P1）
JSON復元、独自CSV取込・出力、重複/競合処理、PWAキャッシュ、アクセシビリティ、オフライン、モバイルの重要E2Eを実装。全受入基準とデモリセットを確認してMVPリリース候補。

## フェーズ6: 外部データ（P2、MVP後）
GBFSの利用条件とスキーマを確認→adapter→期限管理→ポート画面。天気providerを選び、API制限を確認。必要なら認証付きLLMサーバーを追加。連携障害でもP0/P1が停止しないこと。

## フェーズ7: 学習（P3）
本人の実績から集計ベースライン→時系列評価→小さな予測モデル→改善確認→段階公開。需要予測の擬似データを実績として学習しない。

## 完成物
アプリソース、lockfile、環境変数の例（秘密なし）、起動README、スキーマ移行、テスト、受入実施記録、データ辞書、デモデータ。画像が後から取得できたらassets/uiへ原本と出典を追加し、数値やラベルの矛盾は計算仕様を優先して修正する。
