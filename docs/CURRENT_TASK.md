## 大事な決めごと

- 2026-10-05 画面の情報密度のルールを `docs/UI_RULES.md` の「4. 情報密度」に決めた（説明は ⓘ、設定済みは1行に畳む、数字はマス目、日時の入力は横に並べない）。精算の「確定したクエスト・ボーナス」は欄の名前を「確定ボーナス」に短くした
- 2026-10-05 E2E は Playwright（版は手元のブラウザーに合わせて 1.56.1 に固定。axe の部品が別の版を連れてこないよう `overrides` で同じ版にそろえる）。PRごとに GitHub Actions で実行する
- 2026-10-05 「文字200%」の確認は、ページの基準の文字の大きさを200%にして行う（画面の文字は rem で決めているので、ブラウザーの文字の拡大と同じ効き方になる）
- 2026-10-05 CSVの二重取込の判定は、記録に持たせた「取り込み元の external_id と行の中身」で行う（仕様 03 の ImportBatch の表は作らない）。中身には CSV の platform 列で指定したサービスも含める（画面で選んだサービスは含めない）。同じIDで同じ中身 → 飛ばす、中身が違う → 上書きせず競合として止める。取り込んだ記録を消した後にもう一度取り込むと、また追加される
- 2026-10-05 CSVの行はすべて確かめてから1回の書き込みで保存する。不正な行・競合・時間の重なりが1つでもあれば、1件も保存しない（部分保存しない）
- 2026-10-05 CSVのレンタル代は時刻を推測せず「実請求額だけのレンタル」、bonus_yen は「確定したクエスト」、direct_expense_yen は「その他の経費」として入れる。どのサービスの記録かは画面で選ぶ（任意の platform 列があればその値）。文字コードは UTF-8 のみ（文字化けを見つけたら保存し直しを案内）
- 2026-10-05 クエストの件数は「期間内に帰宅した、対象サービスの確定記録の完了件数」＋手入力の調整。達成分は見込みとして表示するだけで、実績の売上には自動で入れない（確定したら精算の「確定したクエスト」に入れる）
- 2026-10-05 休憩前の返却の比較は「借りたまま：F(経過＋休憩＋休憩後) − F(経過)」と「返して借り直す：F(休憩後)」。今までの料金はどちらでも同じなので比べない
- 2026-10-05 データの版を4に上げ、記録に取り込み元（`imported`：external_id と行の中身）を追加。版1〜3のバックアップも読み込める（取り込み元なし＝手入力として）
- 2026-10-05 データの版を3に上げ、クエスト（`quests`）を追加。版1・2のバックアップも読み込める
- 2026-10-05 GO/WAIT/STOP の判定：締切超え → STOP。必要な値の不足（目標未設定・料金対象外・見込み未入力・延長0分）→ WAIT。楽観でも目標未満 → STOP、悲観でも目標以上 → GO、その間 → WAIT。増えるレンタル代は「延長して返す時点の料金 − 今やめて返す時点の料金」（仕様 §5）
