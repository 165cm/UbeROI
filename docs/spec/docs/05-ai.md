# 05 AI機能仕様
## 役割分担
数値計算はドメイン関数、判定は検証可能なルール、LLMは理由の言語化。LLM出力で保存済み売上や料金を変更しない。少ない実績から精度や達成確率を保証しない。

|機能|入力|出力・実装段階|不足時|
|---|---|---|---|
|稼働枠推薦|曜日・時間・実績・予算時間|P1手動シナリオ/P3学習による週の配分|手動見込み値を要求|
|料金最適化|料金版・貸出/返却時刻|P1段階料金と限界利益|料金不明ならWAIT|
|クエスト価値|条件・残件数・期限・件数分布|P2到達確率と限界期待報酬|確率算出不可と表示|
|エリア学習|粗いエリア・時間・収益・件数|P3個人実績ヒートマップ|件数と未学習を表示|
|店舗学習|匿名店ラベル・待ち時間|P3待ち時間分布と所要時間補正|全体分布へ縮約|
|終了地点価値|帰宅時間・ポート・将来需要|P3続行と終了の比較|帰宅所要を手入力|
|ポート推薦|GBFS・徒歩距離・返却予定|P2距離と在庫に基づく候補|古い値は順位に使わない|
|終了助言|追加売上/費用/時間・締切|P1 GO/WAIT/STOP|推定不足ならWAIT|
|事前受注ルール|目標時給・所要分布・終了予定|P3最低単価と時間帯別目安|一般論の断定をしない|
|週次コーチ|計算済みKPI・差分|P2改善点3件と根拠|ルール文章へfallback|

## コールドスタートと学習
0件はデモと手動入力だけ。1〜9セッションは本人の平均を参考として表示し「学習不足」。10件以上で比較表示を許すが十分な精度の保証とはしない。時間帯×エリアの細分化は各セル10セッション未満なら全体へ縮約する。天候でさらに分割する時は検証が必要。
P3の初期モデルは説明可能な集計/回帰を候補にし、最新のセッションをホールドアウトする時系列検証を行う。将来の確定売上、終了後の天気、結果としてのクエスト達成を予測入力へ混入させない。MAE（純利益・時給）と区間の被覆率を、全体平均ベースラインと比較して改善がなければ学習モデルを公開しない。
悲観/標準/楽観の手動幅は統計的な信頼区間と呼ばない。モデル版、期間、標本数、データ鮮度を全推薦に保持する。

## クエスト計算の詳細
追加ボーナスを単純な1件単価として全件に加算しない。
単一閾値ならEV=B*P(残り必要件数を期限内に完了)。注文/延長の価値にはEV_after-EV_beforeを加える。
複数段階が累積報酬B1,B2,...ならEV=Σ(Bk-Bk-1)*P(N>=nk)（B0=0）。段階ごとの追加報酬形式なら差分を取らず各追加額を用いる。
条件に合わない配達は件数に含めない。実績では確定した明細だけを計上し、予測EVと合算しない。標本不足なら0%/100%を創作せず不明にする。

## LLM説明の制約
送信データは計算済み集計値、粗いエリア、判定、根拠に限定。店舗名・メモ・取込ファイルは信頼できないデータとして扱い、そこに書かれた指示を実行しない。
システム指示案: 「あなたはUbaROIの説明担当。提供された数値と判定を変更しない。根拠のない需要・料金・確率を補わない。不足は不足と説明する。出力はsummary、reasons最大3件、caveatsのJSON。」
検証: 架空KPI、異なるGO判定、未提供の確率、長すぎる応答、不正JSONは破棄して定型説明を表示。助言は短くし、操作をする場合は停止中の利用に限る。
