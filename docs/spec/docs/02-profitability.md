# 02 収益性と計算仕様（正本）
## 基本規約
JPYの入力は整数円。時間はUTCのISO日時で保存、表示/週/月境界はAsia/Tokyo、週は月曜開始。区間は[start,end)。内部計算は整数/十進数で行い、表示時だけ円を四捨五入する。期間をまたぐ稼働はMVPでは帰宅日のセッションとして集計し、画面にこの集計基準を表示する。
利益は税引前の管理指標。法定の減価償却や税務上の経費判定を実装したものではない。

## 1. 時間
H=(帰宅-出発)/3600秒。移動・待機・休憩を含む本人の拘束時間。
O=オンライン区間の和集合の時間（時間単位）。A=配達受諾から完了までの区間の和集合。複数同時配達を単純加算しない。
待機率=(O-A)/O。Aがオンライン外にある場合は入力不整合を出し、強制補正しない。O=0はnull。店舗待ちは到着→商品受取、空走は別区間で任意入力し、待機と合算して拘束時間へ二重加算しない。

## 2. 売上と費用
R=基本報酬+チップ+確定クエスト/ボーナス+符号付き調整。
簡易モードではセッション集計値、詳細モードでは配達明細合計を採用。両方を足さない。ボーナスは一意の明細IDで1回だけ計上。期待クエスト値は実績売上に入れない。
C=レンタル費+稼働に直接伴う経費+継続固定費の配分額。
レンタルは実請求額があればそれを優先し、見積と差額を残す。固定費は当月の確定セッションへH比で配分。月に稼働がない固定費も月次損益には残す。月途中は暫定配分、過去月の記録変更で再計算する。個別セッションの確定とは別に期間レポートは再計算可能とする。
P=R-C（営業純利益）。営業純時給=P/H。売上時給=R/O。配達中売上時給=配達由来売上/A（ボーナスを含めるか明示、既定は含めない）。1件平均営業利益=P/完了件数。レンタルコスト率=レンタル費/R。
分母が0ならnullと「算出不可」。赤字は負値のまま表示。

## 3. シェアサイクルの段階料金
料金は事業者・地域・車種・時期で変わるため、利用者がプリセットから選ぶか自分で入力し、利用時の公式表示を優先する。特定地域の料金を唯一の既定値にしない。
以下の数値と表は、プリセット例「HELLO CYCLING 東京都シティサイクル」（開始30分160円、以後15分160円、12時間まで上限2,500円、秒は1分へ切上げ）での計算例。他の段階料金も同じ式に各値を入れて計算する。
貸出が開始している場合、m=max(1,ceil(実経過秒/60))。
0<m<=上限対象分数に限定して F(m)=min(上限額,初期額+加算額*ceil(max(0,m-初期分数)/加算分数))。例: F(m)=min(2500,160+160*ceil(max(0,m-30)/15))、m<=720。
未開始はF=0。開始済み0秒は初期料金（例では160円）。上限対象時間（例では720分）超はMVPの見積対象外（null、「実請求額を入力」）とし上限を延々据え置かない。複数レンタルは各貸出を別々に計算し合計する。
次課金時刻は「Fが次に増える最小秒」。例では30分ちょうどで160円、30分1秒で320円。上限到達後は上限対象時間まで「追加課金なし」、残時間0とは表示しない。予測対象が対象外範囲に入れば助言を抑止する。

|実利用時間|料金|
|---|---:|
|30:00|160|
|30:01|320|
|45:00|320|
|45:01|480|
|60:00|480|
|120:00|1120|
|180:00|1760|

例の料金では、原案の「4時間15分〜上限」は厳密な境界ではない。秒切上げルールに従い4時間を超えた時点で上限になる。
時間パス（例: 3時間○円）や月額サブスク・自前車両（貸出ごとの料金なし）も料金の種類として選べるようにする。

## 4. 初期投資と管理配賦
装備iの現金投資Ii=単価×数量×業務使用割合。購入済みだけを対象とし、予定は計画のみ。既存所有品は今回現金投資0、任意の管理用価値を入力する。
月額配賦Di=(管理対象価値-残存額)/配賦月数。残存額は管理対象価値以下。業務割合は管理対象価値を作る際に一度だけ適用する。
利用開始月からNか月に均等配賦する（初月日割りなし）。最後の月で端数を調整して総額が一致。月額を当月セッションのH比で配分する。稼働0の月でも月額は月次レポートから消えない。
投資配賦後利益=P-D、配賦後時給=(P-D)/H。購入額Iiをここでさらに引かない。

現金ベースの累積営業余剰G=累積売上-累積レンタル支払-累積経費支払（固定費も支払日）。現金投資累計Iは購入日に計上。
投資込み累積キャッシュ=G-I+装備売却回収額。回収残額=max(0,I-G-売却回収額)。購入前の予定額を実績回収残額へ足さない。
回収率=(G+売却回収額)/I、投資ROI=(G+売却回収額-I)/I。I=0ならnull。負の回収率を0に切り捨てない。100%超も数値表示。
予測回収月数=回収残額/予測月間営業余剰。分母<=0は「回収見込みなし」。端数月を保持し、予測ラベルと前提時間を表示。追加購入があれば回収済み状態は再評価する。

## 5. 予測と継続判断
将来の追加純利益ΔP=追加売上期待値+クエスト期待値の増分-追加レンタル-追加経費-返却失敗期待費用。
追加レンタル=F(延長して返却する時点)-F(今から返却する時点)。すでに支払う費用は再控除しない。ΔHは「今帰る場合」と「延長して帰る場合」の帰宅時刻差。ΔH<=0は比較不可。
追加純時給=ΔP/ΔH。GOは目標以上かつ帰宅期限内。STOPは期限超過または上限シナリオでも目標未達。WAITは入力/推定不足または判定がシナリオによって変わる場合。走行中操作を促さない。
必要売上=目標時給×H+C（投資配賦後目標の場合は+D）。現金投資一括回収目標は別シナリオ。
週の配分は重複しない候補枠から、ΣH<=利用可能時間、帰宅期限内でΣ予測営業利益が最大になる組合せを選ぶ。負の利益枠は選ばない。時給順に選ぶだけでは最適解とは限らない。

### 5.1 売上見込み（計算版2）
候補枠・延長分の標準シナリオの売上見込みRは、上から順に最初に使えるものを使う。悲観・楽観は R×0.8・R×1.2 の手動の幅。
1. 同じ時間帯の確定実績が10回以上：R=Σ売上/Σ拘束時間（その時間帯）×H×k
2. 確定実績が全体で10回以上：R=Σ売上/Σ拘束時間（全体）×H×k
3. エリアの混み具合があり、枠の一部でも入力済み：R=1400×Σ(各1時間区切りの長さ×段階倍率)。段階倍率は 1=0.60・2=0.85・3=1.10・4=1.35、未入力の時間は時間帯倍率。月倍率は掛けない
4. それ以外：R=1400×Σ(各時間帯区切りの長さ×時間帯倍率)×月倍率。時間帯倍率は早朝0.55・ランチ1.10・昼下がり0.65・ディナー1.20・夜0.85・深夜0.55、月倍率は1月から順に1.10・0.90・1.00・0.90・0.95・1.05・1.10・1.10・1.05・0.95・0.90・1.15
k は混み具合の補正：k=（枠の平均段階倍率）÷（平均に使った実績の拘束時間で重み付けした平均段階倍率）を0.5〜2に制限。どちらかが未入力なら k=1。
混み具合の表は日本時間の4時〜翌3時を1日とし、0〜3時は前の曜日の表を見る。段階はエリアの中での比較で、時給そのものではない。

### 5.2 オファー判定（計算版3）
報酬Y・分M・距離L（任意）・余裕B（分、既定5）から：
- 増えるレンタル代Rr：レンタル中なら F(経過+M+B)−F(経過)（料金表の対象外なら下の目安）。それ以外は 1分あたりの目安×(M+B)。目安は段階料金=加算の料金÷加算の分、時間パス=各パスの料金÷分の最小、自前=0
- 実質時給 h=(Y−Rr)÷(M+B)×60。分単価=Y÷M、km単価=Y÷L
- 届け先エリア（地名から探す。なければ主なエリア）の、配達を終える時刻（今+M）の段階で基準を変える：基準T=目標時給×倍率（段階1=1.15・2=1.05・3=0.95・4=0.90、不明=1）
- 判定：配達を終えて家に着く時刻（今+M+家までの分）が帰宅締切を過ぎる→断る（締切の日付は稼働の出発時刻の後で最初のその時刻。出発時刻が分からない時は、その日の配達の始まり＝日本時間4時の後で最初のその時刻）。目標未設定→微妙（時給だけ表示）。h≧T→受ける、h≧0.8T→微妙、それ未満→断る。km単価が下限（任意）を下回れば1段下げる
- 承諾の操作はしない。画面の文字の読み取りは利用者のショートカットが行い、アプリは受け取った文字を読むだけ
- 届け先の地名×時間帯の学習した評価（5.3、10件以上）があれば、上の段階は表の値の代わりにその評価を使う（計算版4）

### 5.3 地名の評価の自動学習（計算版4）
オファーの記録（受けた・断った）から：
- 受けたオファー（地名あり）ごとに、配達を終える時刻（時刻＋M）から次のオファーの時刻までの待ちW＝max(0, 次の時刻−終える時刻)（分）。次がない・W＞60分（休憩・終了とみなす）は数えない
- 地名×時間帯（配達を終える時刻の日本時間。朝4〜10時・昼10〜14時・午後14〜17時・夕方17〜21時・夜21〜翌4時）ごとに、Wの中央値を出す
- 段階：中央値≦3分→4、≦7分→3、≦12分→2、それより長い→1
- 件数が10以上の地名×時間帯だけを判定に使う。記録しなかったオファーは数えない
- 設定コード（ショートカットの URL）にも、10件以上の評価を入れて渡す。Safari では、設定コードの評価と Safari にたまった記録の評価のうち、同じ地名×時間帯は件数の多い方を使う（重なる記録を二重に数えないため足さない）。iPhone の Safari に残った記録は「持ち帰りコード」でホーム画面のアプリへ移す（同じIDは重ねない）

### 5.4 終了までの見通し（計算版5。エリアの移動は計算版6）
稼働中、終了予定（配達をやめる時刻）E を決めると、今 t から E までの使い方を比べる。E は入力した時刻のうち t の前後12時間に入るもの（初期値は帰宅締切−家までの分を15分単位で切り下げ、t より前なら t。締切がなければ2時間後の正時）。すでに稼いだ分はどれを選んでも同じなので比べない。
- 今日のここまでの売上 S：出発の後に「受けた」と記録したオファーの報酬の合計（手入力があればそれ）
- ペースの比 p＝S ÷ 出発から今までの普段の見込み（5.1）。出発から45分未満・S がない時は出さない。見込みに掛ける倍率 k＝1＋(min(1.5, max(0.5, p))−1)×0.5（半分だけ反映）
- 行動ごとのこの先の売上 V＝区間の普段の見込み×k。このまま続ける＝[t, E)、休憩して再開＝[t＋休憩, E)（休憩は30・60分、休憩の後に30分以上働ける時だけ）、エリアを移動＝移動先の混み具合で出した [t＋移動の分, E) の見込み×k（主なエリアからの移動の分を登録したエリアだけ。着いてから30分以上働ける時だけ。計算版6）、今やめる＝0
- 増えるレンタル代：借りたまま＝F(今の経過＋返却まで＋休憩か移動＋働く時間)−F(今の経過＋返却まで)（移動の間は乗っているので借りたまま）。休憩する時は、休憩中に返して借り直す F(働く時間) の方が安ければそちら。今やめる＝0
- この先の利益＝V−増えるレンタル代。時給＝利益÷働く時間
- おすすめ：目標時給 T があれば「利益 − T × 働く時間」（目標を上回る分）が最大の行動。T がなければ利益が最大の行動。休憩は2つの長さのうちこの値が大きい方だけ、移動はエリアのうちこの値が一番大きい1つだけを候補にする。移動は手間と外れのリスクがあるので、移動しない一番良い行動より200円以上良い時だけ選ぶ（混み具合の段階はエリアの中での比べっこなので、エリア同士の比較は目安と表示する）。最大の行動と今やめるの差が200円未満なら今やめる。終了予定＋家までの分（返却の時間を含む）が帰宅締切を過ぎる時は、終了予定を早めるよう伝える
- 参考：最後のオファーからの分と、普段のオファーの間隔（記録の間隔の中央値。60分より空いたところは除く、5件未満は出さない）。間隔の2倍（15分以上）止まっていれば知らせる
- 見込みは目安で、確定した記録には入れない

## 6. 基準例（すべて合成値）
H=3時間、O=2.5時間、R=7180円、レンタル1760円、他経費200円、固定費0円。
P=5220円、営業純時給1740円、売上時給2872円。配賦600円なら配賦後利益4620円、時給1540円。
I=30000円、G=5220円、売却0なら回収残24780円、回収率17.4%、投資ROI=-82.6%。
原案のR=7180、経費がレンタルのみの場合はP=5420、時給1806.67円。この違いはその他経費の有無であり丸め誤差ではない。
