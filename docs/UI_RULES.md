# 画面のルール（UI_RULES）

## 1. 文字は最小限

- 伝えるべきことは伝え、くり返しと毎回の説明は削る
- 毎回読まなくていい説明は ⓘ（押すと出る吹き出し）に入れる
- 意味が伝わるところは、絵文字＋短い言葉
- 押した結果は、押した場所の近くで返す。取り消せる操作には「↩ 元に戻す」

## 2. スマホ1画面の密度

- スマホが基本（縦 390×844 で確認）。横持ち・パソコンでも崩れないこと
- 主な操作のボタンは押せる大きさ（高さ44px以上）
- 1画面に主な目的は1つ

## 3. 色・形（このリポジトリ用）

- 下のメニューは「今日／計画／記録／分析」の4つ。設定はヘッダーのリンクから開く
- 幅320〜1440pxで崩れない。横スクロールしてよいのはデータの表だけ
- 利益・損失や GO/WAIT/STOP を**色だけで伝えない**（文字や記号も付ける）。赤字はマイナスの数字のまま出す
- 文字を200%に拡大しても使える。キーボードと読み上げソフトで操作できる
- 「予測」「見積」「推計」「デモ」は、実績と見分けがつくようにラベルを付ける
- 計算できない値は「算出不可」と出し、0円や空欄でごまかさない
- 主な色：昼は白に近い背景（#f4f6f3）と深緑（#166b45）、夜は深緑の背景（#101815）とミント（#64d9a0）。提案は青、料金の注意は琥珀色。フォントは端末のシステム書体を優先する。

## 4. 情報密度（このリポジトリ用。2026-10-05）

- 毎回読まなくていい説明は、見出しや入力欄のラベルの横の ⓘ（`Tip`／`CardTitle` の `tip`／入力欄の `tip`）に入れる。いつも見せるのは、今の状態で変わること（入力の誤り・計算した値・警告）だけ（入力欄の `hint`）
- 数字は「小さなラベル＋値」のマス（`dl.stats`）を横に並べる。長い値は `div.wide` で1行を使う
- 設定済みのもの（基本設定・料金・装備の品目・固定費・候補枠・クエスト）は1行に畳む。押すと編集欄が開く（`details.fold`、または ✏️）。初めて入れる時や、名前のない新しい品目は開いたまま
- 一覧の中の小さな操作は、文字なしのアイコンボタン（`button.icon`・44px）に `aria-label` を付ける。カードの追加は見出しの右の「＋」
- 日時の入力（`datetime-local`）は横に並べない（狭い画面で時刻が隠れるため）。それ以外の短い入力は2〜3個を横に並べてよい
- 画面の名前を見出しにも表示する
- ⓘ の押せる範囲は36px、一覧のアイコンボタンは44px、主な操作のボタンは52px以上
- 画面ごとの仕様：`docs/spec/docs/01-product-spec.md` の S01〜S08

## 混み具合の色

- 混み具合の段階は、信号の色で表す：4 混む＝緑、3 やや混む＝黄緑、2 やや空き＝オレンジ、1 空き＝赤（`--busy-1`〜`--busy-4`。暗い表示用の色もある）
- 赤と緑は見分けにくい人がいるので、色だけに頼らず、段階の数字を必ず一緒に出す（棒の上に重ねる）。読み上げでは「段階4 混む」のように伝える
- 例外：計画の「📅 いつ働くか」の7日の帯は、1時間のマスが細く数字が入らないため、混み具合の色を背景として薄く敷くだけにする（読み上げでは読まない）。段階の数字は、ホームの表・設定 → エリアで出す

## 計画の画面（2026-10-06）

- 目的は「この週の稼働量を決める」こと。開いた時に、上から順に ⏱️ この週の稼働（実績・これから・上限までの残りの時間と、見込み利益）→ 📅 いつ働くか（7日の帯）→ 🧭 今週の作戦（選択肢のボタン：おすすめ・最低・本命・クエストを気にしない。日数・時間・件数・利益・時給・レンタル代・クエストの報酬）→ 📅 いつ働くか → 🎯 クエスト を出す
- 3つの見込みの比べ方・候補枠の一覧・エリアの順番・装備の回収は「📋 くわしく見る」に畳む
- 選んだ作戦の時間は帯に 🧭（紫の点線）で出し、帯の下に「🧭 おすすめ：1日・10h・約29件・利益◯円」と日ごとの一覧（時間・件数・売上・🚲レンタル代（借りたまま／間で返す）・ピーク）と＋。設定の働ける時間の外は斜線
- 帯の日ごとに天気（☀️☁️☔⛈️。押すと 晴れ→くもり→雨→荒天→予報 と手で直す。手で直した日は枠で囲む）。雨の時間は帯の下に青い線、荒天は赤い斜線。出典「天気：Open-Meteo（気象庁）」を帯の下に出す
- 候補枠の追加は「📅 いつ働くか」の見出しの右の＋、日ごとの＋、作戦の＋。帯の四角を押すとその枠の編集


## UI刷新 第1段階（2026-10-07）

- 計画の上に初期設定を置き、週に使える時間が未設定なら自動提案は出さない。
- 上部の集計は「登録済み候補」、作戦は「未登録の提案」と表示する。提案追加は文字付きボタン。
- 未設定の仮条件・参考値を含む推計は、ⓘに隠さず表示する。
- 今回の変更方針は `UI_REDESIGN.md` を参照。

## UI刷新 第2段階（2026-10-07）

- 稼働中は時間・レンタル・精算を最初に表示。クエストとお釣りを続け、終了見通しと継続判断を「このあとどうする？」にまとめる。
- 帰宅済みの時間は要約し、修正時に開く。レンタルの時刻も修正時だけ開く。保存は下部に追従し、固定費と装備費が月の分析に入ることを明記する。
- 週間計画の各日に「登録済み／提案」と具体的な時間帯を文字で表示する。
- 分析に記録がない場合は、記録・未精算への入口を表示。稼働0でも固定費を隠さない。

## UI刷新 第3段階（2026-10-07）

- カードは角丸16px、本文の行間は1.6。補足文は14pxを基準にし、稼働時間・利益は大きく表示する。
- 下部メニューと設定は線画アイコンと文字を併用する。選択中のメニューは下線でも示す。
- レンタルの料金上限・休憩比較は必要時に開く。精算の保存欄には入力から計算した利益と時給を併記する。
- 明暗表示は端末設定に従い、動きを減らす設定にも従う。

## UI刷新 第4段階：デザイン案どおりの画面（2026-10-07）

- 正本はユーザーから届いたデザイン案（4画面：今日・昼／今日・夜／週間計画／帰宅後の精算）。色見本を色の名前にする：昼の背景 `--bg #F4F6F3`、夜の背景 `#101815`、主な操作 `--accent #166B45`（夜はミント）、見込み・提案 `--estimate #3869B1`、注意・警告 琥珀（`--attention-bg`・夜は `#F4B544`）
- 頭の部分：太い斜めの緑のロゴ（文字）・今日の日付・「✓ 端末内で記録」（オフラインの時は「📴 オフライン・記録できます」）・設定の歯車。「今日」は画面の見出しを出さない（読み上げには残す）
- 今日（稼働中）：上から「今日の稼働」（稼働中の札・出発からの時計・配達終了予定）→「レンタル料金（見積）」（大きい金額・琥珀の帯に次の課金まで mm:ss と次回 +円・枠線の「↩ 返却を記録」）→「クエスト」（件数・棒・あと何件で＋何円・「件数を記録」「お釣り」）→「📋 判断のたすけ」（畳む。開いたかは端末に覚える）。「帰宅して精算」はメニューのすぐ上に固定
- 帰宅後の精算：上に「←」と題（今日の精算／精算／記録の編集）と日付。時間の帯 → 売上 → 経費 → 「件数・天気・メモを追加」（畳む。入っている時だけ開く）→ 緑の箱（今日の利益・実質時給・計算明細）→ 下に固定の「精算を保存」「下書き保存」。金額の欄は右寄せの大きい数字
- 週間計画：題の下に週の切り替えと「週の上限・働ける時間」。「予定／提案」の切り替え（最初は提案・選んだ方は青）。提案は青いカード（N時間 / N日・見込み利益・未採用）→ 日ごとの行 → 「条件と計算根拠を見る」（畳む）→ 下に固定の「この提案を予定に追加」。予定は稼働の量と7日の帯
- 大きい数字は等幅の数字（`.num`）にし、文字200%でもはみ出さないよう画面の幅も上限にする

## 事後レビュー（2026-10-08）

- ヘッダーは保存場所を案内する。オンライン状態を保存成功の根拠にしない。
- 配達終了予定は帰宅時刻と区別する（家までの移動時間を含まない）。
- 精算の補足欄は初期値がある時に開き、その後は利用者の開閉操作を優先する。
